# 지역 때문에 429가 뜰 때: 프록시 설정과 Vertex 중계 함수

Vertex AI를 쓰는데 유독 429(혼잡 · 한도 초과)가 자주 뜨고, VPN을 켜면 풀리는 경우가 있습니다.
정확한 원인은 구글이 밝히지 않았지만, **요청이 어느 나라 IP에서 오느냐**에 따라 결과가 달라지는 것으로 보입니다.

앱(프론트엔드)만으로는 IP를 바꿀 수 없습니다. 요청은 내 컴퓨터에서 구글로 바로 나가기 때문입니다.
그래서 요청이 **다른 곳을 거쳐서** 나가게 해야 합니다. 방법은 두 가지이고, 둘 중 하나만 하면 됩니다.

| | 방법 1: 바깥 프록시 | 방법 2: 중계 함수 |
|---|---|---|
| 필요한 것 | 이미 쓰고 있는 VPN · 프록시 프로그램 | 구글 클라우드 프로젝트 (Vertex 쓰는 그 프로젝트) |
| 설정 | 연결 설정에 주소 한 줄 | 구글 클라우드 콘솔에서 10분쯤 |
| 요청이 나가는 곳 | VPN의 출구 나라 | 구글 미국 서버 |
| VPN을 계속 켜 둬야 하나 | 예 (프로그램은 켜 둠, 전체 VPN은 꺼도 됨) | 아니요 |
| 폰(iOS 앱 · 웹 전용)에서도 되나 | 아니요 (PC의 드림랜드 서버로 실행할 때만) | 예 |

---

## 방법 1: 이 연결만 VPN · 프록시로 내보내기

컴퓨터 전체에 VPN을 켜는 대신, **AI 요청만** VPN 프로그램을 거쳐 나가게 합니다. 다른 인터넷은 평소대로 씁니다.

1. VPN · 프록시 프로그램을 켭니다. 대부분의 프로그램은 "로컬 프록시 포트"를 열어 둡니다.
   - Clash 계열: `http://127.0.0.1:7890`
   - v2rayN: `socks5://127.0.0.1:10808` (또는 `http://127.0.0.1:10809`)
   - 프로그램 설정에서 "포트", "Mixed port", "HTTP/SOCKS 포트" 같은 항목을 찾으면 됩니다.
2. 드림랜드 → **연결** → 쓰는 연결을 엽니다.
3. 아래쪽 **고급 설정**을 펼쳐 **바깥 프록시 주소** 칸에 위 주소를 적습니다.
4. 평소처럼 대화합니다. 이 연결의 요청은 그 프록시를 거쳐 나갑니다.

알아 둘 점

- `http://`와 `socks5://` 주소를 씁니다. 아이디·비밀번호가 필요한 HTTP 프록시는 `http://아이디:비밀번호@주소:포트`로 적습니다. 비밀번호가 필요한 SOCKS5는 지원하지 않습니다.
- `start.bat`(드림랜드 서버)로 실행할 때만 동작합니다. 브라우저는 프록시를 직접 고를 수 없어서, 서버가 대신 보냅니다.
- 칸을 비우면 원래대로 돌아갑니다.
- VPN 프로그램이 꺼져 있으면 "프록시 연결 실패"라고 나옵니다.

## 방법 2: Vertex 중계 함수 (구글 클라우드에 직접 올리기)

내 구글 클라우드 프로젝트에 **작은 중계 함수**를 미국 리전에 올립니다. 드림랜드는 Vertex 대신 이 함수에 요청을 보내고,
함수가 그대로 Vertex에 넘깁니다. Vertex 입장에서는 요청이 **구글 미국 서버에서** 온 것이 됩니다.

커뮤니티에 돌아다니는 "버텍스를 URL + API 키로 쓰는 법", "429 뜨면 프록시로 연결" 글도 원리는 이것과 같습니다.
이 폴더의 코드는 그 글의 코드와 무관하게 드림랜드용으로 새로 쓴 것이고, 훨씬 단순합니다:
**형식을 바꾸지 않고 그대로 전달만** 합니다. 인증(서비스 계정이나 API 키)은 지금 드림랜드에 넣어 둔 것을 그대로 씁니다.

### 올리는 순서

1. [구글 클라우드 콘솔](https://console.cloud.google.com)에 들어가, 위쪽에서 **Vertex를 쓰는 프로젝트**가 선택돼 있는지 확인합니다.
2. 왼쪽 메뉴 → **Cloud Run** → **함수 작성**(Write a function).
   처음이면 Cloud Build · Cloud Run 같은 API를 켜겠냐고 묻습니다. 켭니다.
3. 설정
   - 서비스 이름: 아무거나 (예: `dreamland-relay`)
   - 리전: **us-central1** (미국)
   - 런타임: **Node.js 22** (20 이상이면 됩니다)
   - 인증: **인증되지 않은 호출 허용**(공개 액세스 허용)
     — 주소에 암호(RELAY_KEY)가 들어가므로, 암호를 모르는 사람은 쓸 수 없습니다.
4. 편집기가 열리면
   - `index.js`의 내용을 전부 지우고 이 폴더의 [`index.js`](index.js) 내용을 붙여 넣습니다.
   - `package.json`의 내용을 전부 지우고 이 폴더의 [`package.json`](package.json) 내용을 붙여 넣습니다.
   - **함수 진입점**(Function entry point) 칸에 `relay` 라고 적습니다.
5. **변수 및 보안 비밀**(Variables & Secrets)에서 환경 변수를 하나 추가합니다.
   - 이름: `RELAY_KEY`
   - 값: 남이 추측하기 어려운 긴 문자열 (영문 · 숫자만, 예: `k7Qm2xV9pL4tR8wZ3nB6`)
6. **저장 및 배포**를 누르고 기다립니다. 끝나면 위쪽에 `https://….run.app` 주소가 나옵니다.
7. 확인: 브라우저에서 `https://….run.app/health` 를 엽니다. `{"ok":true,"key":true}` 가 보이면 됩니다.
   (`"key":false` 이면 5번의 RELAY_KEY가 저장되지 않은 것입니다.)

### 드림랜드에 연결

1. 드림랜드 → **연결** → 쓰던 **Vertex 연결**을 엽니다 (서비스 계정이든 키든 그대로 둡니다).
2. **주소** 칸에 다음을 적습니다.

   ```
   https://….run.app/여기에_RELAY_KEY
   ```

   예: `https://dreamland-relay-123456.us-central1.run.app/k7Qm2xV9pL4tR8wZ3nB6`
3. 리전 · 프로젝트 ID · 모델은 평소대로 둡니다. 대화해 봅니다.

주소 칸을 비우면 원래대로 Vertex에 직접 연결합니다.

### 알아 둘 점

- **비용**: Cloud Run은 매달 무료 사용량이 있고, 혼자 대화하는 정도는 보통 그 안에 들어갑니다. 다만 무료 범위와 요금은 구글이 정하므로 콘솔의 결제 화면에서 직접 확인하세요. 모델 사용료(Vertex)는 지금과 똑같이 나옵니다.
- **보안**: RELAY_KEY가 들어간 주소는 비밀번호처럼 다루세요. 주소가 새도 남이 내 모델을 쓸 수는 없지만(인증은 요청마다 드림랜드가 붙입니다), 함수 호출 횟수는 내 계정에 잡힙니다. 새면 RELAY_KEY를 바꾸고 다시 배포하면 됩니다.
- **이 함수가 하는 일**: `/v1/projects/…` 와 `/v1/publishers/…` 로 시작하는 Vertex 주소만 넘깁니다. 다른 주소로는 아무것도 보내지 않습니다. 대화 내용을 저장하거나 기록하지 않습니다.
- **효과**: 이 방법으로 429가 줄었다는 사례가 있지만, 모든 계정에서 통한다고 확인된 것은 아닙니다. 계정 자체의 한도 때문에 뜨는 429는 이 방법으로 풀리지 않습니다.
- 콘솔의 메뉴 이름은 구글이 가끔 바꿉니다. 이름이 조금 달라도 "Cloud Run에서 Node.js 함수를 인라인 편집기로 만든다"는 흐름은 같습니다.

## 방법 3: Cloudflare 중계 (무료 · 카드 없이 · 가장 쉬움)

방법 2와 같은 일을 Cloudflare Workers 에서 합니다. 커뮤니티에서 "버텍스 cloudflare 세팅"으로 돌던 방법과 원리가 같습니다:
요청이 내 IP 대신 **Cloudflare 서버**에서 나가고, 워커의 **배치(Placement)** 를 미국 지역으로 두면 VPN 으로 미국을 고른 것과 같아집니다.

드림랜드 안에 안내가 들어 있습니다: **연결 → Vertex 연결 → "429가 잦으면: 중계 쓰기 (Cloudflare · Vercel)"**.
워커 코드 복사 · 암호 만들기 · 주소 확인 · 이 연결에 쓰기까지 그 창에서 합니다. 코드는 이 폴더의 `cloudflare-worker.js` 입니다.

- 워커에는 구글 키를 넣지 않습니다. 드림랜드가 지금처럼 키를 붙여 보내고, 워커는 그대로 전달만 합니다.
- 여러 프로젝트를 번갈아 쓰려면: 다른 프로젝트의 서비스 계정으로 연결을 하나 더 만들고(같은 중계 주소 사용 가능), 첫 연결의 **안 되면 이 연결로**에 골라 두세요. 429 가 나면 그쪽으로 한 번 다시 보냅니다.
- 답이 안 오면 워커 설정의 배치 지역만 다른 곳으로 바꿔 보세요.

## 방법 4: Vercel 중계 (무료 · 카드 없이 · GitHub 계정만)

`relay/vercel` 폴더가 그대로 Vercel 프로젝트입니다. 한 번 배포하면 미국 4곳(iad1 · pdx1 · cle1 · sfo1)과 유럽 2곳(fra1 · lhr1)이 함께 열립니다.
주소는 `https://….vercel.app/<지역>/<RELAY_KEY>` 꼴이고, 앱이 여섯 곳을 모두 등록해 **429 가 나면 다음 지역으로 자동으로 넘어갑니다** (통한 지역은 기억합니다).
앱 안의 같은 안내 창에서 **Vercel** 을 고르면 "Vercel 에 배포" 단추가 있습니다. 누르면 이 폴더가 내 GitHub 에 복사되고 배포되며,
그 과정에서 `RELAY_KEY`(중계 암호)를 묻습니다. 배포가 끝나면 나오는 `https://….vercel.app` 주소를 안내 창에 붙여넣고 "이 연결에 쓰기"를 누르면 됩니다.

## 함께 쓰면 좋은 것: 429 자동 재시도 (기본 꺼짐)

연결 → 고급 설정 → **429 자동 재시도**. 429 가 나면 잠깐 쉬었다 같은 연결로 다시 보냅니다 (글자가 오기 전만).
추천값은 **2회 · 2초**. 같은 요청을 다시 보내는 것이라 기다리는 시간이 늘고, 업체 · 중계에 따라 막힌 요청도 요청 수나 요금에 셀 수 있습니다.
하루 한도를 다 써서 나는 429 는 다시 보내도 풀리지 않습니다.

## 지역 자동 전환

한 지역에서만 계속 나가면 그 지역도 결국 429 가 납니다. Vertex 연결의 주소 칸에 중계 주소를 **빈칸이나 쉼표로 나눠 여럿** 적으면,
429 가 날 때 기다리지 않고 다음 주소로 넘어가고, 통한 주소를 기억해 다음에도 거기부터 씁니다. 모두 429 면 한 바퀴만 돌고 멈춥니다.
Vercel 은 안내 창이 여섯 지역을 알아서 등록합니다. Cloudflare 는 워커를 지역만 달리해 여러 개 만들어 주소를 모두 적으면 됩니다.

### 중계를 다 돌아도 429 일 때

중계는 요청이 **나가는 곳(IP)** 만 바꿉니다. 주소 속 Vertex **리전**은 그대로라서, 그 리전(특히 `global`)이 붐비면 중계를 몇 개 돌아도 429 가 납니다.
Vertex 의 Gemini 는 리전마다 처리 용량을 따로 나눠 쓰므로, 이럴 때는 리전 자체를 바꾸는 쪽이 듣습니다.

1. **429 때 옮겨 볼 리전** (연결 → 서비스 계정 칸 아래): 「추천 리전 넣기」를 누르거나 `us-central1, europe-west4, asia-northeast1` 처럼 적습니다.
   429 가 나면 기다리지 않고 다음 리전으로 옮겨 보내고, 답을 받은 리전에서 30분 동안 시작합니다. 그 모델이 없는 리전은 한 번 확인한 뒤 하루 동안 건너뜁니다.
   중계와 같이 쓸 수 있습니다(중계 주소는 그대로, 리전만 바뀜). 프로젝트 ID 가 있어야 하고, 익스프레스 키만으로는 안 됩니다.
   새로 나온 미리보기 모델은 `global` 에만 있는 경우가 많아, 그때는 이 방법이 통하지 않습니다.
2. **대체 연결 줄**: 연결마다 「안 되면 이 연결로」를 정해 두면 A → B → C 로 차례로 넘어갑니다(최대 4개). Vertex 와 AI Studio(Gemini API 키)는 서로 다른 몫을 쓰므로,
   Vertex 연결 뒤에 AI Studio 연결을 두거나, 다른 구글 프로젝트의 연결 · 같은 연결의 가벼운 모델(Flash 등)을 두면 붐빌 때 끊기지 않습니다.
3. **보조 호출은 알아서 비켜 섭니다**: 같은 연결로 답변이 나가는 동안, 그리고 그 연결에서 429 가 난 직후 잠깐은 기억 정리 · 번역 · 선택지 같은 보조 호출이 늦게 나갑니다.
   본 답변과 보조 호출이 한꺼번에 몰려 같이 막히는 일을 줄입니다. 보조 호출을 아예 다른 연결로 돌리려면 기능 › 보조 연결에서 고릅니다.
4. **429 자동 재시도**(고급 설정)는 위 방법을 다 쓴 뒤의 마지막 수단입니다. 붐빔이 몇십 초 안에 풀리는 경우에 듣습니다.

## 계정 하나로 나가는 곳(IP 지역)을 더 늘리기

버텍스 429 는 요청이 **어느 지역에서 들어오느냐**를 탈 때가 있습니다 (global 주소는 요청이 들어온 곳 가까운 구글 쪽 처리 용량을 쓰는 것으로 보입니다).
계정 · 프로젝트를 늘리지 않고도, 요청이 나가는 곳을 여러 지역으로 늘리면 한 지역이 막혀도 다른 지역에서 통할 수 있습니다. Vercel(6곳) 말고도 무료로 지역을 고를 수 있는 곳이 있습니다.

| | 지역 | 고르는 방법 | 무료 · 카드 |
|---|---|---|---|
| Vercel (`relay/vercel`) | 미국 4 · 유럽 2 | 지역마다 함수 하나 | 무료 · 카드 없음 |
| **Cloudflare (`relay/cloudflare`)** | 미국 동 · 서, 서유럽, 동유럽, 남미, 오세아니아, 아시아 (워커 하나로) | 지역을 정해 띄운 Durable Object 가 구글로 보냄 | 무료 · 카드 없음 |
| **Supabase (`relay/supabase`)** | 미국 3 · 캐나다 · 유럽 4 · 남미 · 호주 · 인도 · 싱가포르 · 도쿄 (함수 하나로) | 요청마다 `x-region` 으로 지역 지정 | 무료 · 카드 없음 |
| 내 PC (`relay/local`) + VPN | VPN 이 나가는 나라 | `VIA` 에 VPN 프로그램 주소 | — |

셋 다 같은 OpenAI 호환 길(키 돌려쓰기 · AI Studio 키 · 버티기 · 대신 쓸 모델)을 쓰고, **`NEXT_RELAY`** 로 서로 이을 수 있습니다:
한 중계의 지역이 다 막히면 다른 곳에 올린 중계의 지역들을 한 바퀴 더 돌고, 그래도 막히면 처음 중계에서 버팁니다.
예) Supabase 중계의 `NEXT_RELAY` = `https://<워커>.workers.dev/v1` → Supabase 13곳 + Cloudflare 7곳을 한 계정으로.

### Cloudflare: 워커 하나로 여러 지역

- 배포 버튼: `https://deploy.workers.cloudflare.com/?url=https://github.com/geminibug2026/DreamLand/tree/main/relay/cloudflare`
  (버튼이 안 되면 드림랜드 폴더에서 `cd relay/cloudflare` → `npx wrangler login` → `npx wrangler deploy`)
- 배포한 뒤 워커 → 설정 → 변수 및 비밀에 `RELAY_KEY`(비밀), `API_1`(서비스 계정 JSON, 비밀) 등을 넣습니다. 나머지 변수는 Vercel 판과 같습니다. `HOP_REGIONS` 로 지역과 순서를 바꿉니다 (`enam wnam weur eeur sam oc apac`).
- 실리태번 · 마리나라: `https://<워커>.<계정>.workers.dev/v1` + API 키 `RELAY_KEY`
- 드림랜드 Vertex 연결: 주소 칸에 지역마다 `https://<워커>.<계정>.workers.dev/enam/<RELAY_KEY>` 처럼 적어 빈칸으로 나누면 429 때 다음 지역으로 넘깁니다 (이 길은 드림랜드의 키를 그대로 씁니다)
- 지역 지정은 Cloudflare 가 "되도록 그 근처"로 맞추는 방식이라 정확한 도시는 보장되지 않습니다.

### Supabase: 함수 하나로 여러 지역

1. supabase.com 에서 프로젝트를 하나 만듭니다 (무료).
2. Edge Functions → 새 함수 → 편집기에서 만들기. 이름은 `relay`. `relay/supabase/index.ts` 내용을 통째로 붙여 넣고 배포합니다.
3. 그 함수의 Details 에서 **Verify JWT with legacy secret(예전 이름 Enforce JWT Verification)을 끄고 Save changes.** (프로그램은 Supabase 토큰이 아니라 RELAY_KEY 를 보냅니다)
   프로젝트를 만들 때 고르는 데이터베이스 지역은 상관없습니다 (중계는 데이터베이스를 쓰지 않고, 함수가 도는 지역은 요청마다 따로 고릅니다).
4. Edge Functions → Secrets 에 `RELAY_KEY`, `API_1` 등을 넣습니다. `HOP_REGIONS` 로 지역과 순서를 바꿉니다.
5. 실리태번 · 마리나라: `https://<프로젝트>.supabase.co/functions/v1/relay/v1` + API 키 `RELAY_KEY`

`relay/cloudflare/src/openai.js` 와 `relay/supabase/index.ts` 는 `relay/vercel/lib/openai.js` 로 만든 사본입니다. 고칠 때는 원본을 고치고 `node relay/check-copies.mjs --fix`.

## 클라우드 없이: 내 PC 중계 (`relay/local`)

Vercel · Cloudflare 에 아무것도 올리지 않고, **내 컴퓨터(또는 안드로이드 Termux)에서** 같은 일을 하는 중계입니다. 실리태번 · 마리나라 · 드림랜드 모두에서 씁니다.
Vercel 중계의 OpenAI 호환 길과 같은 코드를 쓰고, 계속 떠 있어서 몇 가지를 더 잘합니다.

- **하루 한도가 찬 키를 기억**해 한 시간 동안 건너뜁니다 (클라우드 함수는 요청마다 새로 떠서 잊어요)
- **버티는 시간에 제한이 없습니다** (Vercel 은 함수 실행 시간 제한이 있어요)
- **VPN · 프록시 프로그램을 거쳐** 보낼 수 있습니다 (`VIA`) — 요청이 나가는 나라를 바꿀 때
- 배포 · 가입 · 카드 등록 없음. Node.js 만 있으면 됩니다 (드림랜드를 쓰고 있다면 이미 있어요)

쓰는 법

1. 드림랜드 폴더의 `relay/local/keys/` 에 키를 넣습니다.
   - 서비스 계정 `.json` 파일을 그대로 (여러 개면 서로 다른 프로젝트의 것으로)
   - `ai-studio.txt` 에 AI Studio 키를 한 줄에 하나씩, `express.txt` 에 Vertex 익스프레스 키를 한 줄에 하나씩
2. `relay/local/start-relay.bat`(Windows) 또는 `sh relay/local/start-relay.sh`(Mac · Linux · Termux)를 실행합니다. 창에 주소와 API 키가 나옵니다.
3. 프로그램에서 "Custom (OpenAI-compatible)" 을 고르고
   - 주소: `http://127.0.0.1:4190/v1`
   - API 키: `local-relay` (바꾸려면 아래 설정의 `RELAY_KEY`)

설정은 `relay/local/settings.example.txt` 를 `settings.txt` 로 복사해 고칩니다: `RELAY_KEY` · `PORT` · `LAN`(1 이면 같은 와이파이의 휴대폰도) · `WAIT_SEC` · `FALLBACK_MODEL` · `VIA` · `MODELS` · `VERTEX_LOCATION`.
`keys/` 와 `settings.txt` 는 깃에 올라가지 않고, `git pull` 이나 `git reset --hard` 로도 지워지지 않습니다.

## 실리태번 · 마리나라 등 다른 프로그램에서 쓰기 (OpenAI 호환)

같은 Vercel 중계에 **OpenAI 호환 길**이 들어 있습니다. 프로그램에서 "Custom (OpenAI-compatible)"을 고르고

- 주소(Endpoint): `https://<내 주소>.vercel.app/v1`
- API 키: `RELAY_KEY` 로 정한 암호

를 넣으면 됩니다. 이 길은 프로그램이 OpenAI 형식으로만 말하므로 **구글 키를 중계에 넣어야** 합니다:
Vercel 프로젝트 → Settings → Environment Variables 에 `API_1` 이라는 이름으로 서비스 계정 JSON 을 통째로 붙여넣고 다시 배포합니다.
프로젝트가 여러 개면 `API_2`, `API_3` … 으로 더 넣습니다 (`API_` 로 시작하면 아무 이름이나 됩니다).

- 429 가 나면 중계가 알아서 차례로 시도합니다. 프로그램 쪽에서 할 일은 없습니다.
  1. 다른 키(다른 프로젝트)로 — 방금 429 를 받은 키는 20초 동안 뒤로 미룹니다
  2. AI Studio 키로 (아래 `STUDIO_1`, 넣었을 때만)
  3. 다른 지역의 함수로 (미국 4 · 유럽 2)
  4. **버티기**: 그래도 다 막히면 연결을 열어 둔 채 3초 · 6초 · 12초 … 쉬며 키를 다시 돌립니다 (`WAIT_SEC`, 기본 60초).
     구글 쪽 전체가 붐벼서 나는 429 는 몇 초 ~ 몇십 초 안에 풀리는 일이 많아 이것이 가장 자주 듣습니다. 프로그램에는 첫 글자가 늦게 올 뿐 오류가 뜨지 않습니다.
  5. `FALLBACK_MODEL` 을 정해 두었으면 그 모델로 한 번 답합니다
- **global 에만 있는 모델(Gemini 4 계열 등)** 은 리전을 바꿀 수 없어서 위 1 · 2 · 4 가 남은 길입니다. 키는 서로 다른 프로젝트의 것이어야 효과가 있습니다.

선택 환경 변수 (Vercel → Settings → Environment Variables, 바꾼 뒤 Redeploy)

| 이름 | 넣는 것 | 기본 |
|---|---|---|
| `API_2`, `API_3` … | 다른 프로젝트의 서비스 계정 JSON (또는 Vertex 익스프레스 키) | — |
| `STUDIO_1`, `STUDIO_2` … | Google AI Studio 의 Gemini API 키 (`AIza…`). Vertex 와 따로 매기는 몫이라 Vertex 가 다 막혀도 통하는 일이 많습니다. 그 모델이 AI Studio 에 없으면 알아서 건너뜁니다 | — |
| `WAIT_SEC` | 모두 막혔을 때 버틸 시간(초). `0` 이면 바로 429 를 돌려줍니다 | `60` (최대 240) |
| `FALLBACK_MODEL` | 끝까지 막히면 한 번 쓸 모델 (예: `gemini-3.7-flash`). 비우면 끔 | — |

`https://<내 주소>.vercel.app/health` 에서 읽힌 키 수(`googleKeys` · `studioKeys`)와 `waitSec` · `fallbackModel` 을 확인할 수 있습니다 (키 값은 보이지 않습니다).
드림랜드에서도 이 길을 쓸 수 있습니다: 연결을 "Custom (OpenAI 호환)"으로 만들고 위 주소와 암호를 넣으면 중계의 키 돌려쓰기 · 버티기를 함께 씁니다.
- `MODELS` 변수에 쉼표로 모델 이름을 적으면 모델 목록에 그대로 나옵니다. 비우면 기본 목록.
- `reasoning_effort`(low · medium · high)를 보내면 추론을 켜고 생각 글을 따로 돌려줍니다. 모델이 그 설정을 받지 않으면 빼고 다시 보냅니다.
- 빈도 · 존재 패널티는 0 이면 보내지 않습니다. 안전 설정은 모두 끕니다.
- Gemini 만 됩니다 (Vertex 의 Claude 는 이 길로 안 됩니다). 함수 호출(도구)은 넘기지 않습니다.
- 배포 링크 (암호와 키를 함께 묻습니다):
  `https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fgeminibug2026%2FDreamLand%2Ftree%2Fmain%2Frelay%2Fvercel&project-name=dreamland-relay&repository-name=dreamland-relay&env=RELAY_KEY,API_1`
