# 지역 때문에 429가 뜰 때: 프록시 설정과 Vertex 중계 함수

Vertex AI를 쓰는데 유독 429(혼잡 · 한도 초과)가 자주 뜨고, VPN을 켜면 풀리는 경우가 있습니다.
정확한 원인은 구글이 밝히지 않았지만, **요청이 어느 나라 IP에서 오느냐**에 따라 결과가 달라지는 것으로 보입니다.

앱(프론트엔드)만으로는 IP를 바꿀 수 없습니다. 요청은 내 컴퓨터에서 구글로 바로 나가기 때문입니다.
그래서 요청이 **다른 곳을 거쳐서** 나가게 해야 합니다. 방법은 두 가지이고, 둘 중 하나만 하면 됩니다.

| | 방법 1: 바깥 프록시 | 방법 2: 중계 함수 |
|---|---|---|
| 필요한 것 | 이미 쓰고 있는 VPN · 프록시 프로그램 | 구글 클라우드 프로젝트 (Vertex 쓰는 그 프로젝트) |
| 설정 | 연결 설정에 주소 한 줄 | 구글 클라우드 콘솔에서 10분쯤 |
| 요청이 나가는 곳 | VPN의 출구 나라 | 구글 미국 서버 |
| VPN을 계속 켜 둬야 하나 | 예 (프로그램은 켜 둠, 전체 VPN은 꺼도 됨) | 아니요 |
| 폰(iOS 앱 · 웹 전용)에서도 되나 | 아니요 (PC의 드림랜드 서버로 실행할 때만) | 예 |

---

## 방법 1: 이 연결만 VPN · 프록시로 내보내기

컴퓨터 전체에 VPN을 켜는 대신, **AI 요청만** VPN 프로그램을 거쳐 나가게 합니다. 다른 인터넷은 평소대로 씁니다.

1. VPN · 프록시 프로그램을 켭니다. 대부분의 프로그램은 "로컬 프록시 포트"를 열어 둡니다.
   - Clash 계열: `http://127.0.0.1:7890`
   - v2rayN: `socks5://127.0.0.1:10808` (또는 `http://127.0.0.1:10809`)
   - 프로그램 설정에서 "포트", "Mixed port", "HTTP/SOCKS 포트" 같은 항목을 찾으면 됩니다.
2. 드림랜드 → **연결** → 쓰는 연결을 엽니다.
3. 아래쪽 **고급 설정**을 펼쳐 **바깥 프록시 주소** 칸에 위 주소를 적습니다.
4. 평소처럼 대화합니다. 이 연결의 요청은 그 프록시를 거쳐 나갑니다.

알아 둘 점

- `http://`와 `socks5://` 주소를 씁니다. 아이디·비밀번호가 필요한 HTTP 프록시는 `http://아이디:비밀번호@주소:포트`로 적습니다. 비밀번호가 필요한 SOCKS5는 지원하지 않습니다.
- `start.bat`(드림랜드 서버)로 실행할 때만 동작합니다. 브라우저는 프록시를 직접 고를 수 없어서, 서버가 대신 보냅니다.
- 칸을 비우면 원래대로 돌아갑니다.
- VPN 프로그램이 꺼져 있으면 "프록시 연결 실패"라고 나옵니다.

## 방법 2: Vertex 중계 함수 (구글 클라우드에 직접 올리기)

내 구글 클라우드 프로젝트에 **작은 중계 함수**를 미국 리전에 올립니다. 드림랜드는 Vertex 대신 이 함수에 요청을 보내고,
함수가 그대로 Vertex에 넘깁니다. Vertex 입장에서는 요청이 **구글 미국 서버에서** 온 것이 됩니다.

커뮤니티에 돌아다니는 "버텍스를 URL + API 키로 쓰는 법", "429 뜨면 프록시로 연결" 글도 원리는 이것과 같습니다.
이 폴더의 코드는 그 글의 코드와 무관하게 드림랜드용으로 새로 쓴 것이고, 훨씬 단순합니다:
**형식을 바꾸지 않고 그대로 전달만** 합니다. 인증(서비스 계정이나 API 키)은 지금 드림랜드에 넣어 둔 것을 그대로 씁니다.

### 올리는 순서

1. [구글 클라우드 콘솔](https://console.cloud.google.com)에 들어가, 위쪽에서 **Vertex를 쓰는 프로젝트**가 선택돼 있는지 확인합니다.
2. 왼쪽 메뉴 → **Cloud Run** → **함수 작성**(Write a function).
   처음이면 Cloud Build · Cloud Run 같은 API를 켜겠냐고 묻습니다. 켭니다.
3. 설정
   - 서비스 이름: 아무거나 (예: `dreamland-relay`)
   - 리전: **us-central1** (미국)
   - 런타임: **Node.js 22** (20 이상이면 됩니다)
   - 인증: **인증되지 않은 호출 허용**(공개 액세스 허용)
     — 주소에 암호(RELAY_KEY)가 들어가므로, 암호를 모르는 사람은 쓸 수 없습니다.
4. 편집기가 열리면
   - `index.js`의 내용을 전부 지우고 이 폴더의 [`index.js`](index.js) 내용을 붙여 넣습니다.
   - `package.json`의 내용을 전부 지우고 이 폴더의 [`package.json`](package.json) 내용을 붙여 넣습니다.
   - **함수 진입점**(Function entry point) 칸에 `relay` 라고 적습니다.
5. **변수 및 보안 비밀**(Variables & Secrets)에서 환경 변수를 하나 추가합니다.
   - 이름: `RELAY_KEY`
   - 값: 남이 추측하기 어려운 긴 문자열 (영문 · 숫자만, 예: `k7Qm2xV9pL4tR8wZ3nB6`)
6. **저장 및 배포**를 누르고 기다립니다. 끝나면 위쪽에 `https://….run.app` 주소가 나옵니다.
7. 확인: 브라우저에서 `https://….run.app/health` 를 엽니다. `{"ok":true,"key":true}` 가 보이면 됩니다.
   (`"key":false` 이면 5번의 RELAY_KEY가 저장되지 않은 것입니다.)

### 드림랜드에 연결

1. 드림랜드 → **연결** → 쓰던 **Vertex 연결**을 엽니다 (서비스 계정이든 키든 그대로 둡니다).
2. **주소** 칸에 다음을 적습니다.

   ```
   https://….run.app/여기에_RELAY_KEY
   ```

   예: `https://dreamland-relay-123456.us-central1.run.app/k7Qm2xV9pL4tR8wZ3nB6`
3. 리전 · 프로젝트 ID · 모델은 평소대로 둡니다. 대화해 봅니다.

주소 칸을 비우면 원래대로 Vertex에 직접 연결합니다.

### 알아 둘 점

- **비용**: Cloud Run은 매달 무료 사용량이 있고, 혼자 대화하는 정도는 보통 그 안에 들어갑니다. 다만 무료 범위와 요금은 구글이 정하므로 콘솔의 결제 화면에서 직접 확인하세요. 모델 사용료(Vertex)는 지금과 똑같이 나옵니다.
- **보안**: RELAY_KEY가 들어간 주소는 비밀번호처럼 다루세요. 주소가 새도 남이 내 모델을 쓸 수는 없지만(인증은 요청마다 드림랜드가 붙입니다), 함수 호출 횟수는 내 계정에 잡힙니다. 새면 RELAY_KEY를 바꾸고 다시 배포하면 됩니다.
- **이 함수가 하는 일**: `/v1/projects/…` 와 `/v1/publishers/…` 로 시작하는 Vertex 주소만 넘깁니다. 다른 주소로는 아무것도 보내지 않습니다. 대화 내용을 저장하거나 기록하지 않습니다.
- **효과**: 이 방법으로 429가 줄었다는 사례가 있지만, 모든 계정에서 통한다고 확인된 것은 아닙니다. 계정 자체의 한도 때문에 뜨는 429는 이 방법으로 풀리지 않습니다.
- 콘솔의 메뉴 이름은 구글이 가끔 바꿉니다. 이름이 조금 달라도 "Cloud Run에서 Node.js 함수를 인라인 편집기로 만든다"는 흐름은 같습니다.

## 방법 3: Cloudflare 중계 (무료 · 카드 없이 · 가장 쉬움)

방법 2와 같은 일을 Cloudflare Workers 에서 합니다. 커뮤니티에서 "버텍스 cloudflare 세팅"으로 돌던 방법과 원리가 같습니다:
요청이 내 IP 대신 **Cloudflare 서버**에서 나가고, 워커의 **배치(Placement)** 를 미국 지역으로 두면 VPN 으로 미국을 고른 것과 같아집니다.

드림랜드 안에 안내가 들어 있습니다: **연결 → Vertex 연결 → "429가 잦으면: Cloudflare 중계 쓰기"**.
워커 코드 복사 · 암호 만들기 · 주소 확인 · 이 연결에 쓰기까지 그 창에서 합니다. 코드는 이 폴더의 `cloudflare-worker.js` 입니다.

- 워커에는 구글 키를 넣지 않습니다. 드림랜드가 지금처럼 키를 붙여 보내고, 워커는 그대로 전달만 합니다.
- 여러 프로젝트를 번갈아 쓰려면: 다른 프로젝트의 서비스 계정으로 연결을 하나 더 만들고(같은 중계 주소 사용 가능), 첫 연결의 **안 되면 이 연결로**에 골라 두세요. 429 가 나면 그쪽으로 한 번 다시 보냅니다.
- 답이 안 오면 워커 설정의 배치 지역만 다른 곳으로 바꿔 보세요.
